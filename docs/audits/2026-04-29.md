**Date:** 2026-04-29
**Auditor:** code-audit skill (Claude Opus 4.7), acquirer + faculty persona
**Scope:** Full-codebase, acquisition framing
**Profile:** Public OSS desktop GUI, Python PyQt6, no stack overlay
**Branch / commit at audit:** `main` @ `771c9bc`

## Verdict

**DO NOT ACQUIRE.**

The codebase is small, clean-formatted, and adequately tested in the abstract. None of that matters. The artifact ships unsigned firmware fetched over the network from a third-party host the maintainer does not control, then writes it directly to user hardware with no authenticity check. A single compromise of `hdzero.go-next.co` — or a CA, or DNS, or an attacker who flips `HDZERO_API_BASE` in a `.desktop` file — bricks every user's HDZero VTX, persistently, in firmware. There is no SECURITY.md, no responsible-disclosure path, no AppImage signing, no real-hardware test gate. An acquirer's diligence team treats this as a class-action waiting to be filed.

The verdict converts to **ACQUIRE WITH REMEDIATION** if and only if the firmware-trust path is closed (signed-firmware verification at download time, or a documented out-of-band verification step the user must perform) AND a published security policy exists.

## Executive Summary

### Strengths (3)

- **Privilege-escalation chain is correct.** Single `pkexec` prompt for the full backup→write→verify pipeline; `shlex.quote` hardens path interpolation; the `&&` short-circuit semantics are deliberate and documented (`flash_ops.py:140-186`, `CLAUDE.md:71`).
- **Test fixture pattern is template-worthy.** `tests/fixtures/fake_flashrom.sh` + synchronous `worker.run()` calls let signal-emitting QThread code be tested deterministically without a real event loop or hardware (`tests/test_flash_integration.py:42-56`).
- **Operational logging is real.** Per-flash transcripts under `$XDG_STATE_HOME/hdzero-programmer/`, line-buffered so a crash mid-flash leaves a debuggable artifact (`app_logging.py:30-45`, `main.py:303-339`).

### Top 5 Blockers (priority:this-week)

1. `#19` BLOCKER SECURITY — Firmware fetched over net flashed to hardware with **zero authenticity check**.
2. `#20` BLOCKER SECURITY — Trust root is third-party host (`hdzero.go-next.co`) outside maintainer's control.
3. `#21` BLOCKER RELEASE — AppImage release ships SHA256SUMS but **no GPG/cosign signature**.
4. `#22` BLOCKER OPS — No real-hardware QA gate. Every test mocks flashrom.
5. `#23` BLOCKER ACQ — No SECURITY.md, no responsible-disclosure channel.

### Estimated Remediation Effort

**8–10 weeks.** Three weeks for #19/#20 (signed-firmware manifest design + verification code + key custody), one week for #21 (signing pipeline + key generation), two weeks for #22 (real-hardware test rig: hardware lands ~2 days), one week for documentation gap (SECURITY.md, ADRs, CONTRIBUTING.md), one to two weeks of remaining MAJOR cleanup. Add slack for review cycles with whoever owns `go-next.co`.

## Refactor Roadmap

### Phase 1 — Pre-Release: close the firmware-trust hole (weeks 1-3)

API contract upgrades to return a manifest including `firmware_url`, `sha256`, and an Ed25519 signature over the manifest. Maintainer's verification public key ships embedded in the application binary; firmware that does not verify is rejected before reaching `FlashWorker`. **Exit criteria:** integration test demonstrates that a tampered firmware blob (any single byte flipped) cannot reach `flashrom -w`. Tickets #19, #20, #21, #22, #23.

### Phase 2 — Hardening: productionize the release pipeline (weeks 4-5)

Bump `actions/upload-artifact` to v4. Register a Forgejo Actions runner so CI is real, not theatrical. Add real-hardware smoke job. Collapse four near-duplicate HTTP workers. Add mypy + coverage gating. Author ADRs for the major decisions. **Exit criteria:** `sha256sum -c SHA256SUMS && gpg --verify SHA256SUMS.asc` documented and tested in CONTRIBUTING.md; CI green on a real PR with no manual intervention. Tickets #24–#31.

### Phase 3 — Goal-Ready: acquirer-readiness paperwork (weeks 6-8)

ADRs, SECURITY.md (already in Phase 1 — sequencing), CONTRIBUTING.md, CODE_OF_CONDUCT.md, issue templates. LICENSE: clean SPDX header, dual copyright line. Trademark investigation. PyQt6 GPL position documented. **Exit criteria:** a senior engineer who has never seen the repo can be productive in one day reading only `README.md`, `CONTRIBUTING.md`, `docs/adr/`, and the codebase. Tickets #32–#43, plus #44 NIT bundle.
